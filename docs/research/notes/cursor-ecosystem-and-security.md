## A1. Rules (.cursor/rules, user/team rules, .cursorrules, AGENTS.md, CLAUDE.md)

### Takeaway
Cursor has four rule sources: Project Rules (`.cursor/rules/**/*.mdc`, frontmatter `description` / `globs` / `alwaysApply`), User Rules (account-synced via Customize, plus machine-local files in `~/.cursor/rules`), Team Rules (dashboard, Team/Enterprise, optionally enforced, may carry globs), and plain-markdown `AGENTS.md` (root + nested). `CLAUDE.md` is read "the same way" as `AGENTS.md` but is always applied. `.cursorrules` is legacy and "will be deprecated". Precedence on conflict: Team > Project > User. Size guidance: keep rules under 500 lines.

### Cited Findings
- Four rule types: Project Rules ("Stored in `.cursor/rules`, version-controlled and scoped to your codebase"), User Rules ("Global to your Cursor environment. Used by Agent (Chat)"), Team Rules ("managed from the dashboard. Available on Team and Enterprise plans"), and AGENTS.md ("Simple alternative to `.cursor/rules`") — [Cursor Docs: Rules](https://cursor.com/docs/rules.md)
- Mechanism: "When applied, rule contents are included at the start of the model context." — [Rules](https://cursor.com/docs/rules.md)
- File format: "Project rules must use the `.mdc` extension. A plain `.md` file in `.cursor/rules` is ignored by the rules system because it has no frontmatter to specify `description`, `globs`, and `alwaysApply`." Subfolders are allowed (`.cursor/rules/frontend/components.mdc`). — [Rules](https://cursor.com/docs/rules.md)
- UI rule types → frontmatter mapping (exact table from docs):
  | `alwaysApply` | `description` | `globs` | Behavior |
  |---|---|---|---|
  | `true` | — | — | Always included. Globs and description are ignored. ("Always Apply") |
  | `false` | — | provided | Auto-attached when a matching file is in context. ("Apply to Specific Files") |
  | `false` | provided | omitted | Agent reads the description and pulls the rule in when relevant. ("Apply Intelligently") |
  | `false` | omitted | omitted | Included only when you `@`-mention the rule in chat. ("Apply Manually", e.g. `@my-rule`) |
  — [Rules](https://cursor.com/docs/rules.md)
- Minimal valid examples (verbatim from docs):
  ```md
  ---
  alwaysApply: true
  ---
  - All source files must include the company copyright header
  ```
  ```md
  ---
  globs: src/components/**/*.tsx
  alwaysApply: false
  ---
  - Use named exports, not default exports
  ```
  ```md
  ---
  description: RPC service conventions and patterns for the backend
  alwaysApply: false
  ---
  - Define each service in its own file under `src/services/`
  ```
  — [Rules](https://cursor.com/docs/rules.md)
- `globs`: "Separate multiple patterns with commas", e.g. `docs/**/*.md, docs/**/*.mdx`; the plugin reference types `globs` as "string or array" — [Rules](https://cursor.com/docs/rules.md); [Plugins reference](https://cursor.com/docs/reference/plugins.md)
- `@file` references inside a rule are NOT inlined: "A file mention like `@migration-template.sql` tells Agent where to look, and Agent reads the file with its tools when it needs the content. The file's contents are not inlined into the prompt, and this is the same in the editor, the CLI, and Cloud Agents." — [Rules](https://cursor.com/docs/rules.md)
- Creation: `/create-rule` in chat (built-in skill) or Customize → Rules → Add Rule; command palette "New Cursor Rule" — [Rules](https://cursor.com/docs/rules.md); [Rules help](https://cursor.com/help/customization/rules.md)
- Size/best practice: "Keep rules under 500 lines"; "Split large rules into multiple, composable rules"; "Reference files instead of copying their contents"; "Start simple. Add rules only when you notice Agent making the same mistake repeatedly." — [Rules](https://cursor.com/docs/rules.md)
- Team Rules: free-form text (no folder structure), support glob patterns (e.g. `**/*.py`); "Enforce this rule" makes it required and non-disableable in Customize; non-enforced team rules can be toggled off by users. "Precedence: Rules are applied in this order: **Team Rules → Project Rules → User Rules**. All applicable rules are merged; earlier sources take precedence when guidance conflicts." — [Rules](https://cursor.com/docs/rules.md)
- User rules storage: account user rules (Customize → Rules) sync across devices; "**User rule files** in `~/.cursor/rules` (Windows: `%USERPROFILE%\.cursor\rules`) stay on the machine and do not sync." — [Rules help](https://cursor.com/help/customization/rules.md)
- Rules apply only to Agent (Chat): "They do not apply to Tab completion, Inline Edit, or Bugbot PR reviews." User Rules are not applied to Inline Edit (Cmd/Ctrl+K). — [Rules help](https://cursor.com/help/customization/rules.md); [Rules](https://cursor.com/docs/rules.md)
- Rules are identified by full path: "Two rules with the same filename in different folders both apply if their conditions match." — [Rules help](https://cursor.com/help/customization/rules.md)
- AGENTS.md: plain markdown without metadata; "Cursor supports AGENTS.md in the project root and subdirectories." Nested files "will be automatically applied when working with files in that directory or its children" and "Instructions from nested `AGENTS.md` files are combined with parent directories, with more specific instructions taking precedence." — [Rules](https://cursor.com/docs/rules.md)
- CLAUDE.md: "Cursor reads `CLAUDE.md` files the same way it reads `AGENTS.md`. Place a `CLAUDE.md` file in your project root and Cursor picks it up automatically. `CLAUDE.md` files are always applied to every conversation, regardless of any `alwaysApply` frontmatter setting." — [Rules help](https://cursor.com/help/customization/rules.md)
- CLI: "The CLI also reads `AGENTS.md` and `CLAUDE.md` at the project root (if present) and applies them as rules alongside `.cursor/rules`." — [CLI: Using Agent](https://cursor.com/docs/cli/using.md)
- `.cursorrules`: "The `.cursorrules` file in your project root is legacy and will be deprecated." Migration: create a rule, paste content, set type to **Always Apply** ("this matches the old behavior"), delete `.cursorrules`. — [Rules help](https://cursor.com/help/customization/rules.md)
- Importing rules from a repo: rules "aren't imported on their own"; package them in a plugin and publish through a marketplace (repo needs `.cursor-plugin/marketplace.json`). — [Rules](https://cursor.com/docs/rules.md)
- Enterprise framing: "rules are suggestions, not guarantees. Combine rules with enforcement hooks for requirements that must be followed." — [LLM safety and controls](https://cursor.com/docs/enterprise/llm-safety-and-controls.md)

### Inferences
- For a cross-tool method kit, `AGENTS.md` (root + nested) is the portable baseline; `CLAUDE.md` also works in Cursor but is always-on, so conditional guidance must go into `.mdc` rules or skills with `paths`.
- Docs do not state whether nested `CLAUDE.md` files (in subdirectories) are honoured the way nested `AGENTS.md` are; the help page only mentions "project root". Treat nested CLAUDE.md in Cursor as unverified.

### Gaps
- No documented byte/token limit for rules or AGENTS.md beyond "under 500 lines".
- Docs do not state the relative ordering of AGENTS.md/CLAUDE.md vs `.mdc` project rules, nor whether `~/.cursor/rules` files accept frontmatter.
- No date/version for nested AGENTS.md or CLAUDE.md support was found in the current docs or in the 1.6–3.0 changelog pages checked.

## A2. Commands (.cursor/commands)

### Takeaway
Commands still exist as a component ("Reusable prompts you invoke with `/` in Agent chat. Commands are markdown files"), but the current docs no longer have a dedicated Commands page; Cursor steers users to Skills (`disable-model-invocation: true` reproduces command behaviour) and ships `/migrate-to-skills` (since 2.4). The only current schema is in the Plugins reference: `commands/*.md|.mdc|.markdown|.txt` with optional `name`/`description` frontmatter.

### Cited Findings
- Component definition: "**Commands** | Reusable prompts you invoke with `/` in Agent chat. Commands are markdown files that define a focused workflow or action." — [Customize Cursor](https://cursor.com/docs/customize-cursor.md)
- Plugin command format: "Commands are markdown or text files defining agent-executable actions. Place them in the `commands/` directory. Commands support `.md`, `.mdc`, `.markdown`, and `.txt` extensions. They can include YAML frontmatter" with fields `name` ("Command identifier (lowercase, kebab-case)") and `description`. Example:
  ```markdown
  ---
  name: deploy-staging
  description: Deploy the current branch to the staging environment
  ---
  # Deploy to staging
  Steps to deploy to staging:
  1. Run tests
  2. Build the project
  3. Push to staging branch
  ```
  — [Plugins reference](https://cursor.com/docs/reference/plugins.md)
- Migration path: "Cursor includes a built-in `/migrate-to-skills` skill in 2.4 that helps you convert existing dynamic rules and slash commands to skills." "**Slash commands**: Both user-level and workspace-level commands are converted to skills with `disable-model-invocation: true`, preserving their explicit invocation behavior." — [Skills](https://cursor.com/docs/skills.md)
- "Set `disable-model-invocation: true` to make a skill behave like a traditional slash command, where it is only included in context when you explicitly type `/skill-name` in chat." — [Skills](https://cursor.com/docs/skills.md)
- Subagent docs: "If a task is single-purpose and doesn't need context isolation, use a skill or command instead." — [Subagents](https://cursor.com/docs/subagents.md)
- Enterprise doc: "Commands are scoped to teams, projects, or users. Team admins can create organization-wide commands that appear for all developers." (its "See Commands" link now points to the Rules help page, i.e. the old commands page is gone) — [LLM safety and controls](https://cursor.com/docs/enterprise/llm-safety-and-controls.md)
- Old URLs `https://cursor.com/docs/agent/chat/commands.md` and `https://cursor.com/docs/context/commands.md` return 404 on 2026-10-14 (checked directly).

- Introduced in 1.6 (Sep 12, 2025): "You can now create reusable prompts and quickly share them with your team. Commands are stored in .cursor/commands/[command].md. Run them by typing / in the Agent input and selecting the command from the dropdown menu." 2.0 added Team Commands defined in the dashboard and shareable via deeplinks. — [Changelog 1.6](https://cursor.com/changelog/1-6); [Changelog 2.0](https://cursor.com/changelog/2-0)
- The sandbox reference still lists `.cursor/commands/` among writable `.cursor` subdirectories ("`rules/`, `commands/`, `worktrees/`, `skills/`, `agents/`"), i.e. the path is still recognised in Oct 2026. — [sandbox.json reference](https://cursor.com/docs/reference/sandbox.md)

### Inferences
- Project commands = plain markdown files `.cursor/commands/<name>.md` invoked as `/<name>` (filename = command name); user-level commands exist ("user-level and workspace-level commands" per the migration skill), presumably `~/.cursor/commands/`, but the user path is not stated in current docs. For new kits, prefer skills with `disable-model-invocation: true`, which is what Cursor's own migration produces.

### Gaps
- No current official doc for argument passing to commands (no `$ARGUMENTS`-style placeholder is documented for commands; `$ARGUMENTS` is documented only for prompt hooks), nor for the user-level commands path.

## A3. Agent Skills (.cursor/skills, SKILL.md)

### Takeaway
Cursor implements the open Agent Skills standard (agentskills.io). Skills are folders with `SKILL.md` (YAML frontmatter `name` + `description` required; Cursor adds `paths`, `disable-model-invocation`, `icon`, `color`, `metadata`; CLI changelog adds `user-invocable`). Discovery: `.agents/skills/`, `.cursor/skills/`, `~/.agents/skills/`, `~/.cursor/skills/`, recursively and in nested project dirs, plus compatibility dirs `.claude/skills/`, `.codex/skills/`, `~/.claude/skills/`, `~/.codex/skills/`. Agent auto-selects by description or user invokes `/skill-name`.

### Cited Findings
- "Agent Skills is an open standard for extending AI agents with specialized capabilities." "When Cursor starts, it automatically discovers skills from skill directories and makes them available to Agent. The agent is presented with available skills and decides when they are relevant based on context." Manual invocation: type `/` and search; "A skill invoked this way attaches to one message. To keep a skill on for the whole session, use it as a Custom Mode with Option+Enter (Mac) or Alt+Enter (Windows)." — [Skills](https://cursor.com/docs/skills.md)
- Skill directories table: `.agents/skills/` (Project), `.cursor/skills/` (Project), `~/.agents/skills/` (User, local machine), `~/.cursor/skills/` (User, local machine). "For compatibility, Cursor also loads skills from Claude and Codex directories: `.claude/skills/`, `.codex/skills/`, `~/.claude/skills/`, and `~/.codex/skills/`." — [Skills](https://cursor.com/docs/skills.md)
- Nested/recursive discovery: "Cursor walks the skills root recursively and picks up any `SKILL.md` it finds"; category folders are organisational, identity = folder containing SKILL.md. A `.cursor/skills/` or `.agents/skills/` anywhere in the repo is picked up and "automatically scoped to files inside that directory". — [Skills](https://cursor.com/docs/skills.md)
- Layout: `my-skill/SKILL.md` plus optional `scripts/` (executable code), `references/` ("Additional documentation loaded on demand"), `assets/` (templates, images, data). "Reference scripts in your `SKILL.md` using relative paths from the skill root." — [Skills](https://cursor.com/docs/skills.md)
- Frontmatter fields (Cursor docs table):
  | Field | Required | Description |
  |---|---|---|
  | `name` | Yes | "Lowercase letters, numbers, and hyphens only. Must match the parent folder name." |
  | `description` | Yes | "what the skill does and when to use it. Used by the agent to determine relevance." |
  | `paths` | No | Glob patterns (comma-separated string or list); skill only surfaced when agent works with matching files. Legacy `globs` "still accepted as a fallback". |
  | `disable-model-invocation` | No | `true` → only included when explicitly invoked via `/skill-name`. |
  | `icon` | No | Badge icon when used as a Custom Mode (e.g. `code`, `terminal`, `bug`, `git-branch`, `book-open`, `beaker`, `shield`, `rocket`). |
  | `color` | No | One of `default`, `green`, `cyan`, `blue`, `purple`, `magenta`, `orange`, `yellow`, `red`, `brand`. |
  | `metadata` | No | Arbitrary key-value mapping. |
  — [Skills](https://cursor.com/docs/skills.md)
- Minimal valid SKILL.md (docs):
  ```markdown
  ---
  name: my-skill
  description: Short description of what this skill does and when to use it.
  ---
  # My Skill
  Detailed instructions for the agent.
  ```
  — [Skills](https://cursor.com/docs/skills.md)
- `user-invocable: false` (CLI): "Set `user-invocable: false` in a skill's `SKILL.md` frontmatter to hide it from `/` autocomplete and typed `/skill-name` resolution while keeping it available to the model." — [CLI changelog](https://cursor.com/docs/cli/changelog.md)
- CLI changelog: "**Skills from other tools' directories.** Skills are also discovered in `.claude/skills`, `.agents/skills`, and `.codex/skills`." — [CLI changelog](https://cursor.com/docs/cli/changelog.md)
- Built-in skills (Cursor-managed): `/automate`, `/autopilot`, `/canvas`, `/create-hook`, `/create-rule`, `/create-skill`, `/create-subagent`, `/cursor-blame`, `/loop`, `/migrate-to-skills`, `/review`, `/review-bugbot`, `/review-security`, `/sdk`, `/shell`, `/split-to-prs`, `/statusline`, `/update-cli-config` (updates `~/.cursor/cli-config.json`), `/update-cursor-settings`. "Agent may also use some built-in skills automatically when your request clearly matches their purpose." — [Skills](https://cursor.com/docs/skills.md)
- Invocation in chat: "Type `/` followed by the skill name in chat to run it (e.g., `/write-tests`), or type `@` and select it to attach as context." — [Skills help](https://cursor.com/help/customization/skills.md)
- Rules vs skills: rules = short guidelines "Included as context in every (or matching) conversation"; skills = multi-step workflows "Invoked on demand". — [Skills help](https://cursor.com/help/customization/skills.md)
- Cloud: "Turn on **Sync Skills for Cloud Agents**" (Settings → Agents → Context and Tools) copies `~/.cursor/skills/` only; `~/.agents/skills/` and project skills elsewhere stay local; admins can disable under Team Settings → Security & Identity. Personal skills can be published to the team Default marketplace (packed into a one-skill plugin). — [Skills](https://cursor.com/docs/skills.md); [Plugins](https://cursor.com/docs/plugins.md)
- Importing skills from a GitHub repo requires packaging them as a plugin with `.cursor-plugin/marketplace.json`. — [Skills](https://cursor.com/docs/skills.md)
- Plugin skills: plugin reference lists only `name`, `description` as skill frontmatter fields. — [Plugins reference](https://cursor.com/docs/reference/plugins.md)

- Open Agent Skills spec (agentskills.io) frontmatter: `name` (required; 1-64 chars, lowercase a-z/0-9/hyphens, no leading/trailing or consecutive hyphens, "Must match the parent directory name"), `description` (required; 1-1024 chars), `license`, `compatibility` (max 500 chars), `metadata` (string→string map), `allowed-tools` ("Space-separated string of pre-approved tools the skill may use. (Experimental)", e.g. `allowed-tools: Bash(git:*) Bash(jq:*) Read`). Progressive disclosure: metadata (~100 tokens) loaded at startup; body "< 5000 tokens recommended" loaded on activation; resources as needed; "Keep your main `SKILL.md` under 500 lines"; keep file references one level deep. Validator: `skills-ref validate ./my-skill`. — [Agent Skills Specification](https://agentskills.io/specification.md)
- Conformance gap: Cursor's documented frontmatter adds `paths`, `disable-model-invocation`, `icon`, `color` (and CLI `user-invocable`) on top of the spec, and does not document `license`, `compatibility` or `allowed-tools` handling. — [Skills](https://cursor.com/docs/skills.md); [Agent Skills Specification](https://agentskills.io/specification.md)

### Inferences
- A single `.claude/skills/<name>/SKILL.md` tree is consumed by both Claude Code and Cursor; `.agents/skills/` is the vendor-neutral path. If both `.cursor/skills/x` and `.claude/skills/x` exist, docs give no precedence rule for skills (subagents do have one: `.cursor/` wins).

### Gaps
- Precedence/deduplication for same-named skills across directories is not documented.
- Whether Cursor honours the spec's experimental `allowed-tools`, or Claude-Code-only frontmatter (`model`, `context: fork`, `argument-hint`, `$ARGUMENTS`), is not documented by Cursor.

## A4. Subagents (.cursor/agents)

### Takeaway
Custom subagents are markdown files with YAML frontmatter in `.cursor/agents/` (project) or `~/.cursor/agents/` (user), with compatibility loading from `.claude/agents/`, `.codex/agents/`, `~/.claude/agents/`, `~/.codex/agents/` (`.cursor/` wins on name clash; project wins over user). Documented frontmatter is only `name`, `description`, `model` (default `inherit`, supports `id[param=value]`), `readonly`, `is_background` — there is NO documented `tools` allowlist field (subagents inherit all parent tools, incl. MCP). Built-ins: `explore` and `browser`. Delegation via the Task tool (automatic by description, explicit `/name`, or natural language); parallel = multiple Task calls in one message; nesting one level deep since 2.5; optional per-subagent git worktree / cloud VM isolation.

### Cited Findings
- Definition: "Subagents are specialized AI assistants that Cursor's agent can delegate tasks to. Each subagent operates in its own context window ... and returns its result to the parent agent." Available "in the editor, CLI, and Cloud Agents". "Subagents start with a clean context. The parent agent includes relevant information in the prompt since subagents don't have access to prior conversation history." — [Subagents](https://cursor.com/docs/subagents.md)
- Modes: **Foreground** ("Blocks until the subagent completes") vs **Background** ("Returns immediately. The subagent works independently."). — [Subagents](https://cursor.com/docs/subagents.md)
- Built-in subagents: **Explore** ("Searches and analyzes codebases ... Uses a faster model to run many parallel searches") and **Browser** ("Controls browser via MCP tools"); FAQ names them `explore` and `browser`. Hook docs also show subagent types `generalPurpose`, `explore`, `shell`. — [Subagents](https://cursor.com/docs/subagents.md); [Hooks](https://cursor.com/docs/hooks.md)
- File locations table: `.cursor/agents/` (project), `.claude/agents/` (project, "Claude compatibility"), `.codex/agents/` (project, "Codex compatibility"), `~/.cursor/agents/`, `~/.claude/agents/`, `~/.codex/agents/` (user). "Project subagents take precedence when names conflict. When multiple locations contain subagents with the same name, `.cursor/` takes precedence over `.claude/` or `.codex/`." — [Subagents](https://cursor.com/docs/subagents.md)
- Configuration fields (exact): `name` (string, optional, default "Derived from filename"; "Use lowercase letters and hyphens"), `description` (string, optional; "shown in Task tool hints. Agent reads this to decide delegation"), `model` (string, default `inherit`; `inherit` or a specific model ID), `readonly` (boolean, default `false`; "restricted write permissions (no file edits, no state-changing shell commands)"), `is_background` (boolean, default `false`). — [Subagents](https://cursor.com/docs/subagents.md)
- Minimal valid example (docs):
  ```markdown
  ---
  name: security-auditor
  description: Security specialist. Use when implementing auth, payments, or handling sensitive data.
  model: inherit
  readonly: true
  ---
  You are a security expert auditing code for vulnerabilities.
  ```
  — [Subagents](https://cursor.com/docs/subagents.md)
- Model parameters syntax: "Append square brackets to a model ID ... Write options as `id=value` pairs", e.g. `composer-2.5[fast=false]`, `claude-opus-5[effort=high,context=300k]`. Configured model is overridden if admin-blocked, not on plan, or legacy request plan without Max Mode ("On legacy request-based plans without Max Mode, subagents run using Composer regardless of any `model` configuration"). — [Subagents](https://cursor.com/docs/subagents.md)
- Tools: "Subagents inherit all tools from the parent, including MCP tools from configured servers." Cloud subagents instead use team MCP servers configured at cursor.com/agents. — [Subagents](https://cursor.com/docs/subagents.md)
- Delegation: automatic based on task complexity, "Custom subagent descriptions", context and tools; "Include phrases like "use proactively" or "always use for" in your description field to encourage automatic delegation." Explicit: `/verifier confirm the auth flow is complete` or natural language ("Use the verifier subagent to ..."). — [Subagents](https://cursor.com/docs/subagents.md)
- Parallel: "Agent sends multiple Task tool calls in a single message, so subagents run simultaneously." Isolation on request: "Each subagent gets its own environment with its own branch: an isolated Git worktree with a separate working directory on the same machine, or its own cloud environment with a dedicated VM ... Changes stay on each subagent's branch until the parent agent merges the results." — [Subagents](https://cursor.com/docs/subagents.md)
- Nesting: "Since Cursor 2.5, subagents can launch child subagents ... The main agent and its direct subagents can launch subagents, but a subagent launched by another subagent can't launch further ones." Hooks or tool policies can block spawning. — [Subagents](https://cursor.com/docs/subagents.md)
- Resume: "Each subagent execution returns an agent ID. Pass this ID to resume the subagent with full context preserved." Background subagent output: `~/.cursor/subagents/`. — [Subagents](https://cursor.com/docs/subagents.md)
- Cloud subagents: `/in-cloud` runs the next task on its own VM and branch; `/autopilot` hands a PR to a cloud subagent (Agents Window, desktop app). — [Subagents](https://cursor.com/docs/subagents.md)
- Cost: "Running five subagents in parallel uses roughly five times the tokens of a single agent." Anti-patterns: "Don't create dozens of generic subagents"; "Start with 2-3 focused subagents"; "A 2,000-word prompt doesn't make a subagent smarter." — [Subagents](https://cursor.com/docs/subagents.md)
- Plugin `agents/` files: frontmatter `name`, `description` only (plugin reference). — [Plugins reference](https://cursor.com/docs/reference/plugins.md)
- Creation helper: built-in `/create-subagent` skill. — [Skills](https://cursor.com/docs/skills.md)

### Inferences
- Claude Code subagent files in `.claude/agents/` load in Cursor, but Claude-specific fields (`tools`, `disallowedTools`, `permissionMode`, `skills`, `hooks`) are not documented by Cursor and should be assumed ignored; tool restriction in Cursor is only `readonly: true` or a `subagentStart`/`preToolUse` hook.
- Model IDs differ between tools (`inherit` is the only portable value).

### Gaps
- No documented `tools` / `allowed-tools` restriction for Cursor subagents; no documented max parallel count.

## A5. Hooks (.cursor/hooks.json)

### Takeaway
Hooks are JSON-configured (`{"version": 1, "hooks": {<event>: [defs]}}`) spawned processes speaking JSON over stdin/stdout. Sources: Enterprise (MDM paths), Team (dashboard, Enterprise), Project `.cursor/hooks.json` (trusted workspace only), User `~/.cursor/hooks.json`, plus Claude Code `settings.json` hooks via third-party import. 21 events (18 agent, 2 Tab, 1 app lifecycle). Exit 0 = use JSON; exit 2 = deny; other = fail-open unless `failClosed: true`. Merge: deny > ask > allow across all sources. Hook defs support `command`, `type` (`command`|`prompt`), `timeout` (s), `loop_limit`, `failClosed`, `matcher` (regex).

### Cited Findings
- "Hooks are spawned processes that communicate over stdio using JSON in both directions. They run before or after defined stages of the agent loop and can observe, block, or modify behavior." — [Hooks](https://cursor.com/docs/hooks.md)
- Full event list: Agent hooks — `sessionStart`, `sessionEnd`, `preToolUse`, `postToolUse`, `postToolUseFailure`, `subagentStart`, `subagentStop`, `beforeShellExecution`, `afterShellExecution`, `beforeMCPExecution`, `afterMCPExecution`, `beforeReadFile`, `afterFileEdit`, `beforeSubmitPrompt`, `preCompact`, `stop`, `afterAgentResponse`, `afterAgentThought`; Tab hooks — `beforeTabFileRead`, `afterTabFileEdit`; App lifecycle — `workspaceOpen` ("Fires when Cursor opens a workspace and on every workspace folder change. Can return additional plugin paths"). — [Hooks](https://cursor.com/docs/hooks.md)
- Minimal valid config:
  ```json
  { "version": 1, "hooks": { "afterFileEdit": [{ "command": ".cursor/hooks/format.sh" }] } }
  ```
  "Project hooks run from the **project root**, so use `.cursor/hooks/format.sh` (not `./hooks/format.sh`)"; user hooks run from `~/.cursor/`. "Cursor watches hooks config files and reloads them automatically." — [Hooks](https://cursor.com/docs/hooks.md)
- Global option: `version` (number, required, "use `1`"). Per-script options: `command` (string, required), `type` (`"command"` | `"prompt"`, default `"command"`), `timeout` (number, seconds, default "platform default"), `loop_limit` (number|null, default `5`; "`null` for Claude Code hooks"), `failClosed` (boolean, default `false`; "hook failures (crash, timeout, non-zero exit code, no output) block the action"), `matcher` (regex; empty or `"*"` matches all). — [Hooks](https://cursor.com/docs/hooks.md)
- Exit codes: "`0` - Hook succeeded, use the JSON output. For permission hooks (`beforeShellExecution`, `beforeMCPExecution`, `beforeReadFile`, `beforeTabFileRead`, `subagentStart`, `preToolUse`), invalid JSON or a response that doesn't match the hook's schema blocks the action." "`2` - Block the action (equivalent to returning `permission: "deny"`)". "Other exit codes - Hook failed, action proceeds (fail-open by default)". — [Hooks](https://cursor.com/docs/hooks.md)
- Prompt hooks: `{"type":"prompt","prompt":"Does this command look safe to execute? Only allow read-only operations.","timeout":10}`; "Returns structured `{ ok: boolean, reason?: string }`"; "`$ARGUMENTS` placeholder is auto-replaced with hook input JSON"; optional `model`. Cloud agents run command hooks only. — [Hooks](https://cursor.com/docs/hooks.md)
- Sources and priority: Enterprise (macOS `/Library/Application Support/Cursor/hooks.json`, Linux/WSL `/etc/cursor/hooks.json`, Windows `C:\ProgramData\Cursor\hooks.json`) → Team (dashboard, Enterprise only, synced "every thirty minutes", OS targeting) → Project (`<project-root>/.cursor/hooks.json`, "run in any trusted workspace") → User (`~/.cursor/hooks.json`). "All matching hooks from every source run, and Cursor merges their responses: any `deny` wins over `ask`, and `ask` wins over `allow`, regardless of source. `user_message` and `agent_message` values are concatenated. For other fields, such as `followup_message`, the last response wins." — [Hooks](https://cursor.com/docs/hooks.md)
- Matcher targets: `preToolUse`/`postToolUse`/`postToolUseFailure` → tool type (`Shell`, `Read`, `Write`, `Grep`, `Delete`, `Task`, `MCP:<tool_name>`); `subagentStart`/`subagentStop` → subagent type; `before/afterShellExecution` → full command string; `beforeReadFile` → `Read`; `afterFileEdit` → `Write`; `beforeTabFileRead` → `TabRead`; `afterTabFileEdit` → `TabWrite`; `beforeSubmitPrompt` → `UserPromptSubmit`; `stop` → `Stop`; `afterAgentResponse` → `AgentResponse`; `afterAgentThought` → `AgentThought`. — [Hooks](https://cursor.com/docs/hooks.md)
- Common input (all hooks): `conversation_id`, `generation_id`, `model`, `model_id`, `model_params` (`[{id,value}]`), `hook_event_name`, `cursor_version`, `workspace_roots`, `user_email`, `transcript_path`. — [Hooks](https://cursor.com/docs/hooks.md)
- Per-event I/O (exact field names):
  - `preToolUse` in: `tool_name`, `tool_input`, `tool_use_id`, `cwd`, `agent_message`; out: `permission` (`"allow"`|`"deny"`; "`"ask"` is accepted by the schema but not enforced for `preToolUse` today"), `user_message`, `agent_message`, `updated_input`.
  - `postToolUse` in: `tool_name`, `tool_input`, `tool_output` (JSON-stringified), `tool_use_id`, `cwd`, `duration` (ms); out: `updated_mcp_tool_output` ("For MCP tools only: replaces the tool output seen by the model"), `additional_context`.
  - `postToolUseFailure` in: + `error_message`, `failure_type` (`error`|`timeout`|`permission_denied`), `duration`, `is_interrupt`; out: `additional_context`.
  - `subagentStart` in: `subagent_id`, `subagent_type`, `task`, `parent_conversation_id`, `tool_call_id`, `subagent_model`, `is_parallel_worker`, `git_branch`; out: `permission` (`allow`|`deny`; "`"ask"` is not supported ... treated as `"deny"`"), `user_message`.
  - `subagentStop` in: `subagent_type`, `status` (`completed`|`error`|`aborted`), `task`, `description`, `summary`, `duration_ms`, `message_count`, `tool_call_count`, `loop_count`, `modified_files`, `agent_transcript_path`; out: `followup_message` (only when `completed`).
  - `beforeShellExecution` in: `command`, `cwd`, `sandbox`; `beforeMCPExecution` in: `tool_name`, `tool_input`, `mcp_server_name`, plus `url`/`mcp_server_url` (HTTP/SSE) or `command` (stdio); out: `permission` (`allow`|`deny`|`ask`), `user_message`, `agent_message`. Docs: "A hook that allows anything it does not recognize should treat a missing or unexpected `mcp_server_name` as a deny"; `failClosed: true` "recommended for security-critical `beforeMCPExecution` hooks".
  - `afterShellExecution` in: `command`, `output`, `duration`, `sandbox`. `afterMCPExecution` in: `tool_name`, `tool_input`, `mcp_server_name`, `mcp_server_url`, `result_json`, `duration`.
  - `afterFileEdit` in: `file_path`, `edits` (`[{old_string,new_string}]`).
  - `beforeReadFile` in: `file_path`, `content`, `attachments` (`[{type: "file"|"rule", file_path}]`); out: `permission` (`allow`|`deny`), `user_message`.
  - `beforeTabFileRead` in: `file_path`, `content`; out: `permission`. `afterTabFileEdit` in: `file_path`, `edits` with `range`, `old_line`, `new_line`; no output.
  - `beforeSubmitPrompt` in: `prompt`, `attachments`; out: `continue` (boolean), `user_message`.
  - `afterAgentResponse` in: `text`. `afterAgentThought` in: `text`, `duration_ms`; no output.
  - `stop` in: `status` (`completed`|`aborted`|`error`), `loop_count`; out: `followup_message` (auto-submitted as next user message; default cap 5 per script via `loop_limit`).
  - `sessionStart` (fire-and-forget) in: `session_id`, `is_background_agent`, `composer_mode` (`agent`|`ask`|`edit`); out: `env`, `additional_context` ("`continue` and `user_message` ... current callers do not enforce them").
  - `sessionEnd` in: `session_id`, `reason` (`completed`|`aborted`|`error`|`window_close`|`user_close`), `duration_ms`, `is_background_agent`, `final_status`, `error_message`; output ignored.
  - `preCompact` in: `trigger` (`auto`|`manual`), `context_usage_percent`, `context_tokens`, `context_window_size`, `message_count`, `messages_to_compact`, `is_first_compaction`; out: `user_message` (observational, cannot block).
  - `workspaceOpen` in: `hook_event_name`, `cursor_version`, `workspace_roots`, `user_email`; out: `pluginPaths` (absolute paths). "Runs in the Cursor desktop app and CLI."
  — [Hooks](https://cursor.com/docs/hooks.md)
- Environment variables to hook scripts: `CURSOR_PROJECT_DIR`, `CURSOR_VERSION`, `CURSOR_USER_EMAIL`, `CURSOR_TRANSCRIPT_PATH`, `CURSOR_CODE_REMOTE`, `CLAUDE_PROJECT_DIR` ("Alias for project dir (Claude compatibility)"). — [Hooks](https://cursor.com/docs/hooks.md)
- Cloud agents: run command-based hooks from repo `.cursor/hooks.json` (and team/enterprise hooks on Enterprise); NOT `sessionStart`, `sessionEnd`, `beforeMCPExecution`/`afterMCPExecution`, Tab hooks, `workspaceOpen`; user-level `~/.cursor/hooks.json` not available; "Hooks do not run during" early read-only turns. — [Hooks](https://cursor.com/docs/hooks.md)
- Debugging: Hooks tab in Customize and a "Hooks" output channel. Built-in `/create-hook` skill. — [Hooks](https://cursor.com/docs/hooks.md); [Skills](https://cursor.com/docs/skills.md)
- Claude Code hook compatibility: loaded when **Include Third-Party Plugins, Skills, and Other Configs** (Settings → Agents → Third-Party Imports, "on by default") is enabled, from `.claude/settings.local.json`, `.claude/settings.json`, `~/.claude/settings.json` (lower priority than all Cursor sources). Mapping: `PreToolUse`→`preToolUse`, `PostToolUse`→`postToolUse`, `UserPromptSubmit`→`beforeSubmitPrompt`, `Stop`→`stop`, `SubagentStop`→`subagentStop`, `SessionStart`→`sessionStart`, `SessionEnd`→`sessionEnd`, `PreCompact`→`preCompact`; `Notification` and `PermissionRequest` unsupported. Tool mapping `Bash`→`Shell`, `Edit`→`Write`, `Glob` unsupported. Both nested `hookSpecificOutput` (`permissionDecision`, `permissionDecisionReason`, `updatedInput`) and flat formats accepted; `decision: "block"` + `reason` on Stop = follow-up. — [Third Party Hooks](https://cursor.com/docs/reference/third-party-hooks.md)
- Partner integrations listed by Cursor: MintMCP, Oasis Security, Runlayer (MCP governance); Corridor, Semgrep (code security); Endor Labs (dependency malware); Snyk Evo Agent Guard (prompt injection/dangerous tool calls); 1Password (secrets). — [Hooks](https://cursor.com/docs/hooks.md)

### Inferences
- For security-critical gates (secret-file reads, destructive shell, MCP allowlisting) set `failClosed: true`; otherwise a crashing/timing-out hook silently allows the action.
- `preToolUse` cannot "ask" today; use `beforeShellExecution`/`beforeMCPExecution` when human confirmation is needed.
- A single script can serve Claude Code and Cursor if it emits the nested `hookSpecificOutput` form and uses exit 2 for deny; reads `CLAUDE_PROJECT_DIR` (set by both).

### Gaps
- Docs give no numeric "platform default" timeout and no Windows-specific execution notes (shell used to run `command` on Windows is not documented); only Windows MDM path is documented.
- Hooks were introduced as beta in 1.7 (Sep 29, 2025), project-level hooks in 2.1, Claude Code hook compatibility in the CLI in 2.4 ([Changelog 1.7](https://cursor.com/changelog/1-7); [Changelog 2.1](https://cursor.com/changelog/2-1); [Changelog 2.4](https://cursor.com/changelog/2-4)); no GA announcement was found.

## A6. Plugins (.cursor-plugin/plugin.json, marketplace.json)

### Takeaway
Cursor loads two plugin formats: Cursor Plugins (`.cursor-plugin/plugin.json`; may bundle rules, skills, agents, commands, hooks, MCP, variables) and open-standard Agent Plugins (root `plugin.json` with `$schema` from agent-plugins.org; skills + MCP only). Multi-plugin repos use `.cursor-plugin/marketplace.json`. Local dev: `~/.cursor/plugins/local/<plugin>`. Marketplace plugins are manually reviewed and must be open source. Team marketplaces: Teams plan 1, Enterprise unlimited.

### Cited Findings
- "Plugins package rules, skills, agents, commands, MCP servers, and hooks into distributable bundles." "Cursor supports the Agent Plugins open standard alongside its own plugin format." — [Plugins](https://cursor.com/docs/plugins.md)
- Formats: "**Agent Plugins**: spec-conformant plugins with a `plugin.json` manifest at the plugin root, packaging skills and MCP servers"; "**Cursor Plugins**: plugins with a `.cursor-plugin/plugin.json` manifest, which add rules, agents, commands, hooks, and variables". Spec: https://agent-plugins.org and https://github.com/agentplugins/agent-plugins-spec — [Plugins](https://cursor.com/docs/plugins.md)
- Variable caveat: "Cursor does not expand the standard's `${PLUGIN_ROOT}` and `${PLUGIN_DATA}` variables in `mcp.json`; use `${CURSOR_PLUGIN_ROOT}` for the plugin root." Also: "Cursor expands `${CURSOR_PLUGIN_ROOT}` and `${CLAUDE_PLUGIN_ROOT}` to the plugin's install path in `command`, `args`, `env` values, and `cwd`." — [Plugins reference](https://cursor.com/docs/reference/plugins.md)
- Cursor Plugin layout (docs):
  ```text
  my-plugin/
  ├── .cursor-plugin/plugin.json   # Required
  ├── rules/*.mdc
  ├── skills/<name>/SKILL.md
  ├── agents/*.md
  ├── commands/*.md
  ├── hooks/hooks.json
  ├── mcp.json
  ├── assets/logo.svg
  ├── scripts/
  └── README.md
  ```
  — [Plugins reference](https://cursor.com/docs/reference/plugins.md)
- Manifest: required `name` ("Lowercase, kebab-case (alphanumerics, hyphens, and periods). Must start and end with an alphanumeric character"). Optional: `description`, `version`, `author` (`name` required, `email` optional), `homepage`, `repository`, `license`, `keywords`, `logo`, `rules`, `agents`, `skills`, `commands` (string or array of paths), `hooks` (path or inline object), `mcpServers` (path, inline object, or array; "Overrides default `mcp.json` discovery"), `variables` (JSON Schema of variable names). — [Plugins reference](https://cursor.com/docs/reference/plugins.md)
- Minimal Cursor plugin manifest: `{"name": "my-plugin"}`; docs example: `{"name":"my-plugin","description":"Custom development tools","version":"1.0.0","author":{"name":"Your Name"}}`. Agent Plugin manifest example: `{"$schema":"https://agent-plugins.org/schemas/1.0.0/plugin.schema.json","name":"my-plugin","description":"Portable code review tools","version":"1.0.0","author":{"name":"Your Name"}}` — [Plugins](https://cursor.com/docs/plugins.md)
- Discovery defaults: Skills `skills/` (each subdir with SKILL.md); Rules `rules/` (all `.md`, `.mdc`, `.markdown`); Agents `agents/` (same extensions); Commands `commands/` (`.md`, `.mdc`, `.markdown`, `.txt`); Hooks `hooks/hooks.json`; MCP `mcp.json`; Root `SKILL.md` = single-skill plugin "only if no `skills/` dir and no manifest `skills` field". "If a manifest field **is** specified ... it **replaces** folder discovery for that component." — [Plugins reference](https://cursor.com/docs/reference/plugins.md)
- Variables: top level must be `{ "type": "object", "properties": { ... } }`; only a fixed set of JSON Schema keywords accepted; values set by admins in dashboard (Plugins → Configure); placeholders `${VAR}` in `mcp.json` (not shell `${env:...}`). — [Plugins reference](https://cursor.com/docs/reference/plugins.md)
- Plugin hooks events list (reference): Agent hooks `sessionStart`, `sessionEnd`, `preToolUse`, `postToolUse`, `postToolUseFailure`, `subagentStart`, `subagentStop`, `beforeShellExecution`, `afterShellExecution`, `beforeMCPExecution`, `afterMCPExecution`, `beforeReadFile`, `afterFileEdit`, `beforeSubmitPrompt`, `preCompact`, `stop`, `afterAgentResponse`, `afterAgentThought`; Tab hooks `beforeTabFileRead`, `afterTabFileEdit`; App lifecycle `workspaceOpen`. — [Plugins reference](https://cursor.com/docs/reference/plugins.md)
- marketplace.json at `.cursor-plugin/marketplace.json` (repo root): required `name` (kebab-case), `owner` (`name` required, `email` optional), `plugins` array ("whole manifest file must be 10 MB or smaller"); optional `metadata` (`description`, `version`, `pluginRoot`). Plugin entry: required `name`; `source` (path string or object with `path`), `description`, `version`, `author`, `homepage`, `repository`, `license`, `keywords`, `logo`, `category`, `tags`, `skills`/`rules`/`agents`/`commands`, `hooks`, `mcpServers`, `variables`. Resolution: looks for `<source>/.cursor-plugin/plugin.json`, merges with entry ("manifest values take precedence"). Example:
  ```json
  {"name":"my-marketplace","owner":{"name":"Your Org","email":"plugins@yourorg.com"},
   "metadata":{"description":"A collection of developer tool plugins"},
   "plugins":[{"name":"plugin-one","source":"plugin-one","description":"First plugin"}]}
  ```
  — [Plugins reference](https://cursor.com/docs/reference/plugins.md)
- Submission checklist includes: all manifest paths relative ("no `..`, no absolute paths"); every `${VAR}` declared; unique kebab-case names; README; public Git repo; submit at cursor.com/marketplace/publish. — [Plugins reference](https://cursor.com/docs/reference/plugins.md)
- Local testing: put plugin in `~/.cursor/plugins/local/my-plugin`, restart or "Developer: Reload Window". On Teams/Enterprise governed by **Allow Local Plugin Imports** (Dashboard → Settings → Security & Identity → Marketplace and Plugins), "off by default on Enterprise". A same-named marketplace install takes precedence over the local copy. Symlinks load only if the target resolves inside that folder. — [Plugins](https://cursor.com/docs/plugins.md)
- Install: Customize → find plugin → Install → choose project or user scope. CLI: `/plugin` to browse/install at user or project scope. — [Plugins](https://cursor.com/docs/plugins.md); [CLI changelog](https://cursor.com/docs/cli/changelog.md)
- Team marketplaces: "available on Teams and Enterprise plans"; "Teams plan: up to 1 team marketplace"; "Enterprise plan: unlimited". Managed in Dashboard → Plugins & MCPs; Import from Repo accepts GitHub, GitLab, Bitbucket, Azure DevOps. Installation modes: **Default Off**, **Default On**, **Required**. Access can be restricted to Organization Groups (SCIM-synced). Auto Refresh (GitHub, needs Cursor GitHub App) re-indexes at most once every 10 minutes. "Serve marketplace from Cursor" option for GitHub imports. Template repo: github.com/fieldsphere/cursor-team-marketplace-template. — [Plugins](https://cursor.com/docs/plugins.md)
- `workspaceOpen` hook "can return plugin paths to load on workspace open". — [Plugins](https://cursor.com/docs/plugins.md)
- Security of marketplace: "Every plugin is manually reviewed before it's listed. All plugins must be open source, and we review each update before publishing." — [Plugins](https://cursor.com/docs/plugins.md)
- MCP install deeplink: `cursor://anysphere.cursor-deeplink/mcp/install?name=$NAME&config=$BASE64_ENCODED_CONFIG` — [Plugins](https://cursor.com/docs/plugins.md)

- Official repo github.com/cursor/plugins ("Cursor plugin specification and official plugins"; ~11.3k stars, pushed 2026-10-14 per GitHub API) contains BOTH `.cursor-plugin/marketplace.json` and `.claude-plugin/marketplace.json` at the root, plus `schemas/plugin.schema.json` and `schemas/marketplace.schema.json`. Official plugins include `teaching`, `continual-learning`, `cursor-team-kit`, `thermos`, `create-plugin`, `ralph-loop`, `agent-compatibility`, `cli-for-agent`, `pr-review-canvas`, `docs-canvas`, `cursor-sdk`, `origin-apps`. — [cursor/plugins](https://github.com/cursor/plugins); [marketplace.json](https://raw.githubusercontent.com/cursor/plugins/main/.cursor-plugin/marketplace.json)
- The official `plugin.schema.json` is closed (`additionalProperties: false`), requires only `name`, and allows: `name`, `displayName`, `description`, `version`, `minClientVersions` ("Minimum client versions required to install the plugin, keyed by client identifier"), `author`, `publisher`, `homepage`, `repository`, `license`, `logo`, `keywords`, `category`, `tags`, `commands`, `agents`, `skills`, `rules`, `hooks` (string path or inline object), `variables`, `mcpServers` (path, inline object, or array). Note `displayName`, `minClientVersions`, `publisher`, `category`, `tags` are in the schema but not in the docs table. — [plugin.schema.json](https://raw.githubusercontent.com/cursor/plugins/main/schemas/plugin.schema.json)
- Real example `ralph-loop/.cursor-plugin/plugin.json`: `{"name":"ralph-loop","displayName":"Ralph Loop","version":"1.0.0",...,"category":"developer-tools","skills":"./skills/","hooks":"./hooks/hooks.json"}`; its `hooks/hooks.json` uses `afterAgentResponse` + `stop` with `"loop_limit": null`. `continual-learning/hooks/hooks.json` uses `"command": "bun run ${CURSOR_PLUGIN_ROOT}/hooks/continual-learning-stop.ts"`; its agent file uses frontmatter `name`, `description`, `model: inherit` and mines `~/.cursor/projects/<workspace-slug>/agent-transcripts/` to update `AGENTS.md`. — [ralph-loop plugin.json](https://raw.githubusercontent.com/cursor/plugins/main/ralph-loop/.cursor-plugin/plugin.json); [continual-learning hooks.json](https://raw.githubusercontent.com/cursor/plugins/main/continual-learning/hooks/hooks.json); [agents-memory-updater.md](https://raw.githubusercontent.com/cursor/plugins/main/continual-learning/agents/agents-memory-updater.md)
- Agent Plugins spec 1.0.0: package = `plugin.json` + `skills/<name>/SKILL.md` (immediate children only, no recursive search) + `mcp.json` + reverse-domain client extension folders (e.g. `com.example.client/hooks/`). Manifest is closed: `$schema` (required, `https://agent-plugins.org/schemas/1.0.0/plugin.schema.json`), `name` (required; 1-64 chars, lowercase ASCII letters, digits, hyphens, periods), `version`, `description`, `author` (`name`,`email`,`url`), `homepage`, `repository`, `license`, `keywords`, `extensions`. Unknown top-level fields are reported and ignored; other schema violations are fatal. `mcp.json` allows only `$schema` + `mcpServers`; transports `stdio` (`type`,`command`; `command` is "one executable token, not a shell command"), `streamable-http` (`type`,`url`), `sse` (deprecated); clients expand `${PLUGIN_ROOT}`/`${PLUGIN_DATA}` in `args`, `env` values, `cwd`; "Configured headers are literal ... must not contain credentials"; no portable OAuth fields. TSC "includes Core Maintainers from Amazon, Cursor, Microsoft, OpenAI, and Vercel." — [Agent Plugins](https://agent-plugins.org/llms.txt); [Plugin manifest](https://agent-plugins.org/plugin-authors/manifest.md)

### Inferences
- A method kit that must ship rules + hooks + agents to Cursor needs the Cursor Plugin format; the Agent Plugins format is enough only for skills + MCP. Cursor's own official repo carries both `.cursor-plugin/marketplace.json` and `.claude-plugin/marketplace.json`, and Cursor expands `${CLAUDE_PLUGIN_ROOT}`, so a dual-manifest repo serving both Claude Code and Cursor is a pattern Cursor itself uses (though not documented as a formal dual layout).

### Gaps
- github.com/cursor/plugin-template was not inspected; Cursor's handling of Agent Plugins `extensions` namespaces is not documented.
- Contradiction to note: Cursor's own repo ships `${CURSOR_PLUGIN_ROOT}` inside a hook `command` string, while the Agent Plugins spec forbids placeholder expansion in `command` (Cursor-format plugins are not bound by that spec rule).

## A7. MCP configuration (.cursor/mcp.json)

### Takeaway
MCP servers are configured in `.cursor/mcp.json` (project) or `~/.cursor/mcp.json` (global) under a top-level `mcpServers` object; stdio entries use `command`/`args`/`env`/`envFile` (`type: "stdio"`), remote entries use `url`/`headers` (+ optional static OAuth `auth`). Interpolation: `${env:NAME}`, `${userHome}`, `${workspaceFolder}`, `${workspaceFolderBasename}`, `${pathSeparator}`/`${/}`. Transports: stdio, SSE, Streamable HTTP; supports Tools, Prompts, Resources, Roots, Elicitation, MCP Apps. Tool calls require approval by default and follow the same Run Modes as terminal commands; pre-approval via `permissions.json` `mcpAllowlist` (`server:tool`) or CLI `Mcp(server:tool)`. Enterprise: MCP Allowlist (command/URL patterns, per-tool allowlists, per-server network modes).

### Cited Findings
- Locations: "Create `.cursor/mcp.json` in your project for project-specific tools." "Create `~/.cursor/mcp.json` in your home directory for tools available everywhere." Also installable from Customize / Marketplace ("Add to Cursor", OAuth). — [MCP](https://cursor.com/docs/mcp.md)
- Minimal stdio example (docs):
  ```json
  { "mcpServers": { "server-name": { "command": "npx", "args": ["-y", "mcp-server"], "env": { "API_KEY": "value" } } } }
  ```
  Remote: `{ "mcpServers": { "server-name": { "url": "http://localhost:3000/mcp", "headers": { "API_KEY": "value" } } } }` — [MCP](https://cursor.com/docs/mcp.md)
- STDIO fields: `type` ("Yes", `"stdio"`), `command` (required), `args`, `env`, `envFile` ("only available for STDIO servers"). — [MCP](https://cursor.com/docs/mcp.md)
- Static OAuth: `"auth": { "CLIENT_ID": "...", "CLIENT_SECRET": "...", "scopes": ["read","write"] }` on `url` entries; fixed redirect URLs `https://www.cursor.com/agents/mcp/oauth/callback` (web/Cursor Agents) and `http://localhost:8787/callback` (desktop). — [MCP](https://cursor.com/docs/mcp.md)
- Interpolation fields: `command`, `args`, `env`, `url`, `headers`; syntax `${env:NAME}`, `${userHome}`, `${workspaceFolder}` ("the folder that contains `.cursor/mcp.json`"), `${workspaceFolderBasename}`, `${pathSeparator}` and `${/}`. — [MCP](https://cursor.com/docs/mcp.md)
- Transports table: `stdio` (local, "Cursor manages", single user, manual auth), `SSE` and `Streamable HTTP` (local/remote, multi-user, OAuth). Protocol features supported: Tools, Prompts, Resources, Roots, Elicitation, Apps (extension). — [MCP](https://cursor.com/docs/mcp.md)
- Programmatic registration via extension API `vscode.cursor.mcp.registerServer()`. — [MCP](https://cursor.com/docs/mcp.md)
- Approval: "Cursor asks for approval before using MCP tools by default." "MCP follows the same Run Modes as terminal commands ... in **Auto-review** mode, allowlisted MCP tools run immediately and everything else is routed through the classifier." — [MCP](https://cursor.com/docs/mcp.md)
- Agent Security page: "All MCP connections need your approval. After you approve an MCP connection, each tool call still needs individual approval before running. You can pre-approve specific tools with an MCP allowlist." — [Agent Security](https://cursor.com/docs/agent/security.md)
- `permissions.json` `mcpAllowlist`: entries `server:tool`, case-insensitive, `*` wildcard (`my-server:*`, `*:my_tool`, `*:*`, `my-server:list_*`); server = key in `mcp.json`; "Entries that do not contain a `:` are ignored." — [permissions.json reference](https://cursor.com/docs/reference/permissions.md)
- Enterprise MCP Allowlist (Team Settings > MCP Configuration): "Command entries approve local `stdio` MCP servers by command pattern"; "URL entries approve remote HTTP/SSE MCP servers"; "Tool allowlists restrict which tools from an approved server can run automatically". Per-server network modes for local servers: Allow all / Allowlist / Deny all / No sandbox; "User MCP Network Denylist" for user MCPs. — [MCP](https://cursor.com/docs/mcp.md)
- CLI: "The CLI will automatically detect and respect your `mcp.json` configuration file". — [CLI: Using Agent](https://cursor.com/docs/cli/using.md)
- Cloud agents / cloud subagents use team MCP servers configured at cursor.com/agents, not local ones; `beforeMCPExecution`/`afterMCPExecution` hooks don't run in cloud agents. — [Subagents](https://cursor.com/docs/subagents.md); [Hooks](https://cursor.com/docs/hooks.md)
- Plugin MCP: `mcp.json` at plugin root; `${CURSOR_PLUGIN_ROOT}`/`${CLAUDE_PLUGIN_ROOT}` expanded; plugin `${VAR}` variables set in dashboard. — [Plugins reference](https://cursor.com/docs/reference/plugins.md)

## B1. Most valuable MCP servers/tools for coding agents

### Takeaway
The most-adopted coding-agent servers in Oct 2026 are documentation retrieval (Context7, ~63k GitHub stars), browser automation/inspection (Chrome DevTools MCP ~53.5k, Playwright MCP ~38k), GitHub's official server (~33.6k) and semantic code navigation (Serena ~30k); database servers are typically vendor-hosted (e.g. Supabase MCP with `read_only`/`project_ref` scoping). Evidence of benefit is mostly vendor/self-reported; independent MCP benchmarks (MCPMark, MCP-Universe, MCP-Atlas) measure general MCP tool use, not the marginal value of particular servers. A notable 2026 trend: vendors (Microsoft Playwright, Context7) now recommend CLI + Skills over MCP for coding agents because tool schemas and verbose outputs cost context; Cursor (2.4) loads MCP definitions lazily for the same reason.

### Cited Findings
- Repository metadata (GitHub API, 2026-10-14): `upstash/context7` 63,024 stars; `ChromeDevTools/chrome-devtools-mcp` 53,515; `microsoft/playwright-mcp` 38,124; `github/github-mcp-server` 33,605 ("GitHub's official MCP Server"); `oraios/serena` 30,256; `modelcontextprotocol/servers` 91,249 (reference servers); `supabase/mcp` 2,950. All actively pushed in Oct 2026. — [GitHub API: context7](https://api.github.com/repos/upstash/context7); [chrome-devtools-mcp](https://github.com/ChromeDevTools/chrome-devtools-mcp); [playwright-mcp](https://github.com/microsoft/playwright-mcp); [github-mcp-server](https://github.com/github/github-mcp-server); [serena](https://github.com/oraios/serena); [servers](https://github.com/modelcontextprotocol/servers); [supabase/mcp](https://github.com/supabase/mcp)
- **Context7** (Upstash): "pulls up-to-date, version-specific documentation and code examples straight from the source — and places them directly into your prompt", addressing "Hallucinated APIs that don't even exist" and outdated examples. Two modes: "CLI + Skills" (`ctx7` CLI, "no MCP required") or MCP. Tools: `resolve-library-id`, `query-docs` (`libraryId` e.g. `/vercel/next.js`). - For a method kit: Context7 (or its CLI+skill mode) and a browser tool (Playwright/Chrome DevTools, or Cursor's built-in browser) give the clearest capability gains; GitHub MCP should run with minimal toolsets, `--read-only` where possible and `--lockdown-mode` on public repos; database MCPs should be read-only and project-scoped, never pointed at production.

- No independent, peer-reviewed measurement found of Context7's or Serena's effect on coding-task success rates; star counts are popularity, not benefit.

## B2. Agent security: risks, incidents, mitigations, permission models

### Takeaway
Across Cursor's 33 and Claude Code's 35 published advisories (to 2026-10-14) and the documented 2025–2026 incidents, the recurring kill chain is: untrusted content (web page, issue/PR text, MCP tool description or output, repo files, skill text) → prompt injection → the agent writes a file that something else executes outside the sandbox or approval flow (MCP config, CLI/permission config, `.git/hooks`/`.git/config`, workspace files, the *other* tool's hook settings, venv interpreters) or abuses an allowlist/parsing gap → code execution or secret exfiltration (often via pre-approved domains). Supply-chain variants (Nx, Amazon Q, Cline, postmark-mcp, ClawHavoc skills) show CI agents and agent extensions themselves are targets. Mitigation consensus (OWASP, MCP spec, Willison, vendors): break the "lethal trifecta", least-privilege/read-only tools and tokens, OS sandbox with deny-by-default egress, protect config paths, pin and review MCP servers/skills/plugins, human approval for consequential actions, fail-closed policy hooks, isolate untrusted repos in VMs/containers; classifiers (Cursor Auto-review, Claude Code auto mode) and content filters (GitHub lockdown) are explicitly not security boundaries.

### Cited Findings
#### Cursor's documented security model
- "AI can behave unexpectedly due to prompt injection, hallucinations, and other issues ... By default, sensitive actions require your manual approval." Reads/searches need no approval; "Agents can modify workspace files without approval, except for configuration files"; terminal commands need approval by default; "All MCP connections need your approval ... each tool call still needs individual approval"; default network: tools only call GitHub, direct link retrieval and web search providers. — [Agent Security](https://cursor.com/docs/agent/security.md)
- "Cursor supports workspace trust, but it's disabled by default ... Restricted mode breaks AI features. For untrusted repos, use a basic text editor instead." Enable with `"security.workspace.trust.enabled": true`. — [Agent Security](https://cursor.com/docs/agent/security.md)
- "Auto-review is not a security boundary. The classifier can make mistakes." Classifier runs on Cursor backend and may make read-only `ReadFile`, `Grep`, `Glob`, `ListDir` calls on your machine. — [Run Modes](https://cursor.com/docs/agent/security/run-modes.md)
- Sandbox: macOS Seatbelt (`sandbox-exec`, Cursor ≥2.0); Linux Landlock + seccomp (kernel ≥6.2 with Landlock v3 and unprivileged user namespaces; otherwise falls back to asking approval; Bubblewrap fallback reported by `CURSOR_SANDBOX_LANDLOCK_STATUS`). Network "Blocked by default" then opened by network mode/`sandbox.json` (default mode "sandbox.json + Defaults" with a built-in package-registry allowlist). Linux sandbox remaps UID to 0 inside a user namespace (use `CURSOR_ORIG_UID`). — [Run Modes](https://cursor.com/docs/agent/security/run-modes.md)
- `sandbox.json` always-write-protected paths: `.cursor/*.json`, `.cursor/**/*.json`, `.cursor/.workspace-trusted`, `.claude/*.json`, `.claude/**/*.json`, `.vscode/**`, `.code-workspace`, `.git/hooks/**`, `.git/config`, `.git/info/attributes`, `.cursorignore`; writable `.cursor` subdirs: `rules/`, `commands/`, `worktrees/`, `skills/`, `agents/`. Private/RFC1918, loopback and `169.254.169.254` blocked "to prevent SSRF". Merge: per-user < per-repo < team-admin < hardcoded; deny beats allow. — [sandbox.json reference](https://cursor.com/docs/reference/sandbox.md)
- Mode-independent protections: Browser Protection, File-Deletion Protection (incl. `rm`), External-File Protection. — [Run Modes](https://cursor.com/docs/agent/security/run-modes.md)
- `.cursorignore` blocks Agent/Tab/Inline Edit/@-mention access but "The terminal and MCP server tools used by Agent cannot block access to code governed by `.cursorignore`"; "complete protection isn't guaranteed due to LLM unpredictability". — [Ignore file](https://cursor.com/docs/reference/ignore-file.md)

#### Claude Code's documented permission/sandbox model (code.claude.com, Oct 2026)
- Permission modes: `default` (labelled Manual), `acceptEdits`, `plan`, `auto` ("a background classifier ... checks that they align with your request"), `dontAsk` (auto-denies anything that would prompt), `bypassPermissions` (skips prompts "including for writes to protected paths such as `.git` and `.claude`" — "Only use this mode in isolated environments like containers or VMs"). Auto mode is the built-in starting mode for interactive terminal and VS Code sessions. `permissions.disableBypassPermissionsMode` / `permissions.disableAutoMode` = `"disable"` (best in managed settings). — [Claude Code: Permissions](https://code.claude.com/docs/en/permissions.md); [Claude Code: Security](https://code.claude.com/docs/en/security.md)
- Precedence: managed settings highest; "If a tool is denied at any level, no other level can allow it"; deny rules from any scope are evaluated before allow rules. Project `.claude/settings.json` `permissions.allow` and `additionalDirectories` apply only after the workspace trust dialog; "A `claude -p` run or an SDK session never shows it". — [Claude Code: Permissions](https://code.claude.com/docs/en/permissions.md)
- Untrusted-repo caveat (exact table): repository-supplied hooks in settings files, the `env` block, `apiKeyHelper`, and a project skill's hooks and `allowed-tools` are "Used" even when only a parent folder was trusted or under `claude -p`; "Workspace trust never gates a skill's `allowed-tools` in any session"; `.mcp.json` servers are "Connected without asking, approved or not" under `claude -p`. Mitigations for `-p` on unknown repos: `--setting-sources user`, `--bare`, `--settings '{"disableAllHooks": true}'`, `disabledMcpjsonServers`. — [Claude Code: Permissions](https://code.claude.com/docs/en/permissions.md)
- Sandbox: "off by default" (enable via `/sandbox` or `sandbox.enabled`); macOS Seatbelt, Linux/WSL2 bubblewrap + socat; writes limited to working dir, temp, added dirs (protected paths write-denied); reads default to "Most of the machine, including credential files such as `~/.ssh` and `~/.aws/credentials`" unless `filesystem.denyRead`/`credentials`; network only via a local proxy with `allowedDomains` that "start empty"; env vars inherited "including any secrets". Built on `@anthropic-ai/sandbox-runtime`. Outside the sandbox: Read/Edit/Write/WebFetch/WebSearch tools (permission rules govern them), hooks, local MCP servers, LSP servers, status line, `!` commands, `excludedCommands`, and "unsandboxed retries" (`dangerouslyDisableSandbox`; disable with `"allowUnsandboxedCommands": false`). Credential masking via sentinel values substituted by the proxy only for `injectHosts`. — [Claude Code: Sandboxing](https://code.claude.com/docs/en/sandboxing.md)
- Prompt-injection safeguards: approval for network commands (`curl`, `wget` not auto-approved), WebFetch returns a separate model's summary rather than raw page for most fetches, command-injection detection (asks before a Bash command "it can't fully analyze"), "Fail-closed matching" in Manual mode, `.mcp.json` approval prompt; best practice "Use virtual machines (VMs) to run scripts and make tool calls, especially when interacting with external web services"; audit settings changes with `ConfigChange` hooks. "Anthropic reviews connectors against its listing criteria ... but does not security-audit" them. — [Claude Code: Security](https://code.claude.com/docs/en/security.md)

### Inferences
- Every file an agent can write that some other component later executes outside the sandbox (git hooks, IDE/workspace config, hook configs of *other* tools such as `.claude/settings*.json`, interpreters invoked by extensions, container runtimes) is an escape path; a method kit that ships hooks/config for both Claude Code and Cursor must assume each tool's config dir is an attack surface for the other (cf. Cursor CVE-2026-48124 and Claude Code CVE-2026-25725).
- Practical baseline for a Cursor + Claude Code kit (derived from the cited docs/advisories): keep both tools auto-updated; Cursor: Allowlist or Auto-review with sandbox on, `sandbox.json` `networkPolicy.default: "deny"` + explicit allow, `readBoundary: "workspace"` (≥3.23), File-Deletion/External-File protection on, `permissions.json` minimal `mcpAllowlist`, fail-closed `beforeShellExecution`/`beforeMCPExecution`/`beforeReadFile` hooks for secrets and destructive commands, `.cursorignore` for secrets (knowing terminal/MCP bypass it), workspace trust enabled for untrusted repos; Claude Code: sandbox enabled with `allowUnsandboxedCommands: false`, `denyRead` for credential paths, deny rules for `curl`/`wget`, `disableBypassPermissionsMode`, `--bare`/`--setting-sources user` for `-p` on foreign repos; both: no `--force/--yolo/--dangerously-skip-permissions` outside disposable VMs; GitHub MCP with minimal toolsets, `--read-only`, `--lockdown-mode`; DB MCP read-only + project-scoped; pin plugin/skill/MCP versions and re-review updates; never give CI agents shell access on events triggerable by outsiders.
- The "two tools read each other's config" design (Cursor loading `.claude/skills`, `.claude/agents`, `.claude/settings*.json` hooks by default via Third-Party Imports) increases the attack surface for repos that only intended to target one tool; Enterprises default this off since Cursor 3.0.
