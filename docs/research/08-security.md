# Every file an agent can write is a potential execution path

Autonomy is only as safe as the boundary around it. The advisories from both vendors read like one recurring kill chain. Untrusted content arrives as a web page, issue text, an MCP tool description or output, a repository file or a skill. It injects instructions. The agent then writes a file that something else later executes outside the sandbox or the approval flow, or it exploits a gap in allowlist parsing. The result is code execution or secret exfiltration. Cursor had published 33 advisories and Claude Code 35 as of 14 October 2026 ([Cursor advisories](https://github.com/cursor/cursor/security/advisories); [Claude Code advisories](https://github.com/anthropics/claude-code/security/advisories)) [V]. They fall into the same five classes.

**Configuration files that execute.** In CVE-2025-54135, creating a new dotfile needed no approval, so injection could write `.cursor/mcp.json` and "trigger RCE on the victim without user approval" ([GHSA-4cxx-hrm3-49rm](https://github.com/cursor/cursor/security/advisories/GHSA-4cxx-hrm3-49rm)). In CVE-2025-54136, an approved MCP config could be silently swapped for a malicious command ([GHSA-24mc-g4xr-4395](https://github.com/cursor/cursor/security/advisories/GHSA-24mc-g4xr-4395)). CVE-2026-26268 (CVSS 8.0, fixed 2.5) was a sandbox escape through writing `.git` configuration and hooks ([GHSA-8pcm-8jpx-hv8r](https://github.com/cursor/cursor/security/advisories/GHSA-8pcm-8jpx-hv8r)).

Most relevant to a dual-tool kit, **CVE-2026-48124** (fixed 3.0.0) had Cursor Desktop executing workspace-defined Claude hook commands from `.claude/settings.local.json` "without dedicated user approval" ([GHSA-pc9j-3qc2-95wv](https://github.com/cursor/cursor/security/advisories/GHSA-pc9j-3qc2-95wv)). On Claude Code's side, CVE-2026-25725 (fixed 2.1.2) let code inside the bubblewrap sandbox create a missing `.claude/settings.json` and inject persistent `SessionStart` hooks that ran with host privileges ([GHSA-ff64-7w26-62rf](https://github.com/anthropics/claude-code/security/advisories/GHSA-ff64-7w26-62rf)). CVE-2026-33068 (fixed 2.1.53) let a repository's `defaultMode: bypassPermissions` silently skip the trust dialog ([GHSA-mmgp-wc2j-qcv7](https://github.com/anthropics/claude-code/security/advisories/GHSA-mmgp-wc2j-qcv7)). Each tool's configuration directory is an attack surface for the other.

**Allowlist parsing gaps.** Claude Code's confirmation prompts were bypassed through `echo`, `rg`, `sed`, `find` and piped `sed`. CVE-2025-55284 combined an "overly broad allowlist of safe commands" to read a file and send it over the network ([GHSA-x5gv-jw7f-j6xj](https://github.com/anthropics/claude-code/security/advisories/GHSA-x5gv-jw7f-j6xj)). In Cursor, CVE-2026-22708 let shell built-ins poison environment variables used by allowlisted commands ([GHSA-82wg-qcm4-fp2w](https://github.com/cursor/cursor/security/advisories/GHSA-82wg-qcm4-fp2w)).

**Exfiltration through pre-approved domains.** In CVE-2026-54316 (fixed 2.1.163), `huggingface.co` was pre-approved for WebFetch, and file downloads that HuggingFace counts server-side formed a covert channel ([GHSA-fg94-h982-f3mm](https://github.com/anthropics/claude-code/security/advisories/GHSA-fg94-h982-f3mm)).

**Supply-chain bypasses.** In CVE-2026-86063 (fixed 2.1.179, published 9 October 2026), a branch named identically to a pinned 40-character plugin SHA installed attacker code ([GHSA-pq7j-f95f-qfcv](https://github.com/anthropics/claude-code/security/advisories/GHSA-pq7j-f95f-qfcv)).

**Direct sandbox escapes.** CVE-2026-50548 and CVE-2026-50549 (critical, fixed in Cursor 3.0) allowed escape through an agent-controlled working directory and through symlinks ([GHSA-3p48-7v9f-v5cw](https://github.com/cursor/cursor/security/advisories/GHSA-3p48-7v9f-v5cw)).

Real incidents follow the same pattern:

| Incident | What happened | Source |
|---|---|---|
| GitHub MCP "toxic agent flow" | A malicious public issue led an agent to leak private-repository data into a public PR. This was an architectural problem, not a server bug | [Invariant Labs](https://invariantlabs.ai/blog/mcp-github-vulnerability) [V] |
| Supabase MCP leak | A Cursor agent connected with `service_role` read a support ticket containing instructions and copied integration tokens into it, with "no permissions … violated" | [General Analysis](https://www.generalanalysis.com/blog/supabase-mcp-blog) [V] |
| Nx "s1ngularity" malware | The payload invoked `claude --dangerously-skip-permissions -p`, `gemini --yolo -p` and `q chat --trust-all-tools` to inventory secrets. About half of victims had an AI CLI installed; almost a quarter of the Claude interactions were rejected | [Nx](https://github.com/nrwl/nx/security/advisories/GHSA-cxm3-wv7p-598c); [Wiz](https://wiz.io/blog/s1ngularitys-aftermath) [V] |
| Cline npm compromise | An issue-triage workflow ran `claude-code-action` with Bash access, triggerable by any GitHub user. Injection plus Actions-cache poisoning stole publish tokens. Cline moved to read-only automation and OIDC publishing | [Cline post-mortem](https://cline.bot/blog/post-mortem-unauthorized-cline-cli-npm) [V] |
| postmark-mcp | A trojanized npm MCP server added a hidden BCC on every outgoing email | [Snyk](https://snyk.io/blog/malicious-mcp-server-on-npm-postmark-mcp-harvests-emails/) [V] |
| ClawHavoc skills | 1,184 malicious skills delivered a macOS stealer through SKILL.md "prerequisite" instructions | [CSA](https://labs.cloudsecurityalliance.org/research/csa-research-note-ai-skill-supply-chain-attacks-20260624-csa/) [V, secondary aggregation] |

The experimental evidence is just as stark. Poisoned rule files achieved 41–84% attack success at making Cursor and Copilot run malicious commands ([arXiv 2509.22040](https://arxiv.org/abs/2509.22040v1); [follow-up](https://arxiv.org/pdf/2605.25871)) [PP]. Invariant Labs showed tool poisoning through hidden instructions in MCP descriptions, "rug pulls" in which a description changes after approval, and cross-server "shadowing" ([Invariant Labs](https://invariantlabs.ai/blog/mcp-security-notification-tool-poisoning-attacks)) [V].

Simon Willison's "lethal trifecta" gives the governing rule. Private data, exposure to untrusted content and the ability to communicate externally together make exfiltration possible, guardrails that are "95%" effective are "a failing grade", and the safe design removes one leg entirely ([Willison](https://simonwillison.net/2025/Jun/16/the-lethal-trifecta/)) [A]. The OWASP Top 10 for Agentic Applications for 2026 codifies the same risks ([OWASP](https://genai.owasp.org/resource/owasp-top-10-for-agentic-applications-for-2026/)), and the MCP specification's security best practices require consent showing "the exact command that will be executed, without truncation" for local server installs ([MCP](https://modelcontextprotocol.io/docs/tutorials/security/security_best_practices)). Both vendors say their classifiers are not security boundaries: Claude Code auto mode and Cursor Auto-review. GitHub says the same of its MCP lockdown mode ([Cursor Run Modes](https://cursor.com/docs/agent/security/run-modes.md); [GitHub MCP](https://github.com/github/github-mcp-server)).

The baseline below is this study's synthesis of the documented controls:

| Control | Claude Code | Cursor | Why |
|---|---|---|---|
| Stay current | Auto-update; several escapes were fixed only in 2.1.x releases | Keep on 3.x; sandbox escapes were fixed in 3.0 and 3.1.2 | Advisories above |
| OS sandbox, failing closed | `sandbox.enabled: true`, `failIfUnavailable: true`, `allowUnsandboxedCommands: false`, `filesystem.denyRead` for `~/.ssh` and `~/.aws` | Sandbox on (Auto-review or Allowlist); `sandbox.json` network deny-by-default plus explicit allows; workspace read boundary (3.23+) | Reads otherwise include credential files |
| Egress control | Deny `curl`/`wget`; `sandbox.network.allowedDomains` starts empty; scoped `WebFetch(domain:…)` | Network "blocked by default", opened by `sandbox.json` | Exfiltration channels |
| Enforcement hooks fail closed | Exit 2, plus `onFailure: "block"` | `failClosed: true`; treat a missing `mcp_server_name` as deny | Both fail open by default |
| No bypass outside disposable VMs | Managed `disableBypassPermissionsMode: "disable"`; never `--dangerously-skip-permissions` on a workstation | No Run Everything, `--force` or `--yolo` outside VMs | The Nx malware relied on exactly these flags |
| Foreign repositories and headless runs | `claude -p` on untrusted repos: `--bare`, `--setting-sources user`, or `--settings '{"disableAllHooks": true}'`, plus `disabledMcpjsonServers` | Enable `security.workspace.trust.enabled`; Enterprises keep Third-Party Imports off | `-p` treats folders as trusted |
| Supply chain | Pin marketplace sources (`sha`), review updates, prefer few plugins | Team marketplace with Required/Default modes; Local Plugin Imports off on Enterprise | postmark-mcp, ClawHavoc, CVE-2026-86063 |
| MCP least privilege | Few servers, scoped tokens, read-only toolsets, subagent-scoped servers | Minimal `mcpAllowlist`; per-server network modes (Enterprise) | Tool poisoning; toxic flows |
| CI agents | No shell on events outsiders can trigger; read-only by default | Same, for Cloud Agents and `agent -p` | Cline compromise |
