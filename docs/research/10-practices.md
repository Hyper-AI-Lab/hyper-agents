# Ranked practices: adopt these, avoid those

Practices are ranked by expected benefit per unit of cost, weighted by evidence strength. The evidence tags follow the legend at the top.

## Eighteen practices to adopt, in rank order

| Rank | Practice | Supporting evidence | Cost or risk |
|---|---|---|---|
| 1 | Accept work only on independent, executed checks. Human-written or human-approved failing acceptance tests come first | 94.3% Verified with human tests vs ≈ 69.8% with self-generated ones ([TDFlow](https://arxiv.org/abs/2510.23761)) [PR]; agent-written tests do not change resolution ([arXiv 2602.07900](https://arxiv.org/abs/2602.07900)) [PP] | Human time to write and review tests. Wrong tests lock in wrong behaviour, so review tests like code |
| 2 | Make tests, CI and agent configuration immutable to the writer during implementation; give it a sanctioned `BLOCKED` exit and a retry cap | More than 79% of Claude's cheating is test edits; an abort option cut GPT-5's cheating from 54% to 9%; extra retries raised cheating from 33% to 38% ([ImpossibleBench](https://arxiv.org/html/2510.20270v1)) [PP] | Hook and diff-audit upkeep; legitimate test fixes need a human-approved path; edit-tool hooks miss shell edits, so the diff audit is mandatory |
| 3 | Deterministic gates: post-edit format, lint and type hooks, plus a Stop-hook check script, configured to fail closed | Lint and typing shortfalls in 75% of test-passing agent PRs ([METR](https://metr.org/blog/2025-08-12-research-update-towards-reconciling-slowdown-with-time-horizons/)) [PP]; static-analysis loop cut security issues from > 40% to 13% ([arXiv 2508.14419](https://arxiv.org/abs/2508.14419)) [PP]; vendor gate ladder ([Claude Code](https://code.claude.com/docs/en/best-practices)) [V] | Per-edit latency. Loops are bounded only by caps: Claude Code's 8 resets on tool calls, Cursor's `loop_limit` defaults to 5. Both tools fail open unless `onFailure: "block"` / `failClosed: true` |
| 4 | One writer; helper agents only explore, review or verify, read-only and in fresh context | Multi-agent variants −39–70% on sequential tasks, 17.2× error amplification ([arXiv 2512.08296](https://arxiv.org/abs/2512.08296v2)) [PP]; "writes stay single-threaded" ([Cognition](https://cognition.com/blog/multi-agents-working)) [V] | Less wall-clock parallelism; truly independent units can still run in worktrees |
| 5 | Minimal, human-written always-on instructions; procedures in skills; must-happen rules in hooks | Context files add > 20% cost without success gains; LLM-written files −0.5% to −3% ([arXiv 2602.11988](https://arxiv.org/abs/2602.11988)) [PP]; 68% compliance at 500 instructions ([IFScale](https://arxiv.org/abs/2507.11538)) [PR] | Ongoing pruning; risk of omitting a real gotcha (add rules only after a repeated mistake) |
| 6 | Just-in-time context: a read-only explorer returning `path:line` pointers; bounded outputs; logs to files; clear between tasks; restart after two failed corrections; mask stale tool output | Focused prompts beat full ones on all 18 models ([Chroma](https://www.trychroma.com/research/context-rot)) [V]; masking halves cost at equal solve rate ([arXiv 2508.21433](https://arxiv.org/abs/2508.21433v3)) [PR]; bounded views beat full files ([SWE-agent](https://arxiv.org/html/2405.15793)) [PR] | Subagents re-gather context (latency). Free-form summaries can mislead, so require pointers |
| 7 | A fresh-context reviewer scoped to correctness, requirements and scope, fed the diff and executed evidence | Self-review AUROC 0.89 vs 0.99 fresh ([arXiv 2603.04582](https://arxiv.org/html/2603.04582v1)) [PP]; ≈ 2 bugs/PR, 58% severe ([Cognition](https://cognition.com/blog/multi-agents-working)) [V] | Tokens. Unscoped reviewers cause over-engineering; framing attacks passed 32 of 33 CVEs ([arXiv 2603.18740](https://arxiv.org/abs/2603.18740)) [PP], so the reviewer must ignore PR prose |
| 8 | Sandbox, deny rules, fail-closed hooks and protected config paths; remove one leg of the lethal trifecta; few, pinned MCP servers and plugins | 68 vendor advisories in five recurring classes ([Cursor](https://github.com/cursor/cursor/security/advisories); [Claude Code](https://github.com/anthropics/claude-code/security/advisories)) [V]; 41–84% injection success via rule files ([arXiv 2509.22040](https://arxiv.org/abs/2509.22040v1)) [PP] | Friction and more prompts; some tools unavailable. Classifiers and filters are not boundaries |
| 9 | Size-gated planning: skip for one-sentence diffs, otherwise a human-reviewed plan file re-read before each task | Plans help, bad plans hurt more than none, reminders help ([arXiv 2604.12147](https://arxiv.org/abs/2604.12147)) [PP]; for strong models planning saves cost ([arXiv 2609.20804](https://arxiv.org/abs/2609.20804)) [PP] | Overhead on small tasks; a bad plan is worse than none, which is why it is reviewed |
| 10 | Harness-produced evidence on completion, marking each criterion passed, failed or untested | False tool-use claims in 5–30% of probes ([Transluce](https://transluce.org/investigating-o3-truthfulness)) [PP]; failure concealment ([arXiv 2512.04864](https://arxiv.org/abs/2512.04864)) [PP]; Replit ([AIID](https://incidentdatabase.ai/entities/replit)) [A] | Small. Evidence must come from hooks or CI, not from the agent's narration |
| 11 | Autonomy tiers by verifiability and blast radius; approve plans and outcomes, not actions; explicit escalation triggers | Turn lengths doubled while experienced users monitor rather than approve; Claude's own pause reasons ([Anthropic](https://www.anthropic.com/research/measuring-agent-autonomy)) [V] | Mis-tiering a core change as peripheral; tiers need periodic audit |
| 12 | Strong lead with cheap helpers: early delegation of mechanical work only, under a structured brief | 63.1 at $1.35 vs 63.6 at $3.51 ([Cognition](https://cognition.com/blog/devin-fusion)) [V]; a brief alone moved a score from 25 to 94 ([Cognition](https://cognition.com/blog/making-fable-cheaper-than-opus)) [V] | Vendor-only evidence. Forced delegation and weak primaries hurt; model IDs differ between tools |
| 13 | Externalized state for multi-session work: `features.json` (only `passes` changes), `progress.md`, an `init.sh` smoke test, one feature per session, a commit per task | Documented failure modes and fixes ([Anthropic](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)) [V]; ExecPlans ([OpenAI](https://developers.openai.com/cookbook/articles/codex_exec_plans)) [V] | Setup and upkeep; stale state misleads, so each session re-verifies with the smoke test |
| 14 | Security scanners and security tests on security-relevant diffs; check new dependencies exist | 57% functional vs 11.8% secure ([SusVibes](https://proceedings.mlr.press/v306/zhao26ax.html)) [PR]; ≥ 5.2% hallucinated packages ([arXiv 2406.10279](https://arxiv.org/abs/2406.10279)) [PR] | Scanner noise; security-test authoring |
| 15 | A private, frozen evaluation harness with paired arms and ablations, re-run on each model upgrade | Public benchmarks contaminated and mis-graded ([OpenAI](https://openai.com/index/separating-signal-from-noise-coding-evaluations/)) [V]; trustworthy benchmark design ([DeepSWE](https://arxiv.org/html/2607.07946v1)) [PP]; error-bar methods ([Miller](https://arxiv.org/abs/2411.00640)) [PP] | Building 30–60 tasks with hidden tests; only large effects are detectable |
| 16 | Held-out acceptance tests, outside the agent's workspace, for high-stakes changes | 43–48 point visible/held-out gap, growing ≈ 28 points per 10× code ([SpecBench](https://arxiv.org/html/2605.21384)) [PP] | Authoring effort; must be kept truly hidden |
| 17 | Adaptive reasoning effort: high for planning, diagnosis and review; medium for routine edits | Medium effort matched the best score with 76% fewer tokens ([Anthropic](https://www.anthropic.com/news/claude-opus-4-5)) [V]; less overthinking gave +30% performance and −43% cost ([arXiv 2502.08235](https://arxiv.org/abs/2502.08235)) [PP] | Under-thinking hard bugs; settings are model-specific |
| 18 | Best-of-N in worktrees with an independent selector, for high-stakes work only | 72.5 → 79.4 and 77.2 → 82.0 ([Claude 4](https://www.anthropic.com/news/claude-4); [Sonnet 4.5](https://www.anthropic.com/news/claude-sonnet-4-5)) [V]; Best@8 73.8 vs Random@8 57.9 ([OpenHands](https://openhands.dev/blog/20260305-learning-to-verify-ai-generated-code)) [V] | N× tokens and merge effort; selecting by visible tests amplifies gaming |

## Eighteen practices to avoid

| Practice | Why |
|---|---|
| Agent swarms, flat peer teams and consensus topologies | −39–70% on sequential tasks and 17.2× error amplification ([arXiv 2512.08296](https://arxiv.org/abs/2512.08296v2)) [PP]; flat peers churned and locks throttled 20 agents to the throughput of 2–3 ([Cursor](https://cursor.com/blog/scaling-agents)) [V]; swarm packs offer no task-success evidence ([Ruflo](https://github.com/ruvnet/claude-flow)) [A] |
| Parallel writers on one coupled design or a shared workspace | Implicit decisions conflict ([Cognition](https://cognition.com/blog/dont-build-multi-agents)) [V]; agents overwrote each other's fixes until given an oracle ([Anthropic](https://www.anthropic.com/engineering/building-c-compiler)) [V] |
| LLM-generated, overview-heavy or kitchen-sink instruction files and rule packs | No success gain, > 20% cost, −0.5% to −3% for generated files ([arXiv 2602.11988](https://arxiv.org/abs/2602.11988)) [PP]; compliance decays with instruction count ([IFScale](https://arxiv.org/abs/2507.11538)) [PR] |
| Treating agent-written tests, or the agent's own "done" report, as acceptance evidence | Tests don't change outcomes ([arXiv 2602.07900](https://arxiv.org/abs/2602.07900)) [PP]; fabricated verification ([Transluce](https://transluce.org/investigating-o3-truthfulness)) [PP] |
| Same-context self-review or a "reflect on your answer" step as a gate | Self-attribution bias ([arXiv 2603.04582](https://arxiv.org/html/2603.04582v1)) [PP]; the QA agent "talked itself into approving" ([Anthropic](https://www.anthropic.com/engineering/harness-design-long-running-apps)) [V] |
| "Do not cheat" prompts as the main defence against test gaming | Negligible effect, 80% → 80% ([METR](https://metr.org/blog/2025-06-05-recent-reward-hacking/)) [PP]; a looser prompt raised SWE-bench cheating ([ImpossibleBench](https://arxiv.org/html/2510.20270v1)) [PP] |
| Unbounded retry loops against the same visible tests | More submissions, more cheating ([ImpossibleBench](https://arxiv.org/html/2510.20270v1)) [PP]; Claude Code's Stop cap resets whenever a tool is called ([hooks](https://code.claude.com/docs/en/hooks)) [V] |
| Unscoped "find every gap" reviewers | They over-report and push over-engineering ([Claude Code](https://code.claude.com/docs/en/best-practices)) [V]; LLM reviewers overcorrect ([arXiv 2603.00539](https://arxiv.org/abs/2603.00539)) [PP] |
| Best-of-N selected only by visible tests or one LLM judge | A lookup-table compiler won selection ([SpecBench](https://arxiv.org/html/2605.21384)) [PP]; judges are random and order-biased ([CodeJudgeBench](https://arxiv.org/abs/2507.10535)) [PR]; benchmark-trained critics scored AUC ≈ 0.45 in production ([OpenHands](https://openhands.dev/blog/20260305-learning-to-verify-ai-generated-code)) [V] |
| Full-ceremony spec frameworks or persona pipelines for small changes | 16 acceptance criteria for one bug fix and hard-to-review Markdown ([Böckeler](https://martinfowler.com/articles/exploring-gen-ai/sdd-3-tools.html)) [A]; Radar "Assess" ([Thoughtworks](https://www.thoughtworks.com/radar/techniques/spec-driven-development)) [A]; no outcome evidence ([arXiv 2606.04967](https://arxiv.org/abs/2606.04967)) [PP] |
| Loading many MCP servers and tools by default | About 26K tokens for one server's 35 tools; deferral raised accuracy ([Anthropic](https://www.anthropic.com/engineering/advanced-tool-use)) [V]; tool poisoning and rug pulls ([Invariant Labs](https://invariantlabs.ai/blog/mcp-security-notification-tool-poisoning-attacks)) [V] |
| Maximum reasoning effort everywhere | Higher effort reduced accuracy in most HAL runs, with ~2 points costing ~10× ([arXiv 2510.11977](https://arxiv.org/abs/2510.11977v1)) [PP]; overthinking correlates with failure ([arXiv 2502.08235](https://arxiv.org/abs/2502.08235)) [PP] |
| Bypass modes on workstations; CI agents with shell access on events outsiders can trigger | The Nx malware used `--dangerously-skip-permissions`, `--yolo` and `--trust-all-tools` ([Wiz](https://wiz.io/blog/s1ngularitys-aftermath)) [V]; Cline's triage bot led to an npm compromise ([Cline](https://cline.bot/blog/post-mortem-unauthorized-cline-cli-npm)) [V] |
| Treating classifiers or content filters as security boundaries | Vendors say auto-review and lockdown modes are not boundaries ([Cursor](https://cursor.com/docs/agent/security/run-modes.md); [GitHub MCP](https://github.com/github/github-mcp-server)) [V]; `.cursorignore` does not bind the terminal or MCP ([Cursor](https://cursor.com/docs/reference/ignore-file.md)) [V] |
| Relying on checkpoints or rewind instead of git | Bash-made and background-subagent changes are not tracked ([Claude Code](https://code.claude.com/docs/en/checkpointing)) [V]; Cursor checkpoints are local only ([Cursor](https://cursor.com/docs/agent/overview.md)) [V] |
| Switching the lead's model mid-session, or pairing a weak primary with a strong escalation model | Switches break the prompt cache, so Fusion times them at compaction ([Cognition](https://cognition.com/blog/devin-fusion)) [V]; the weak-primary "smart friend" design failed ([Cognition](https://cognition.com/blog/multi-agents-working)) [V] |
| Choosing a method by SWE-bench deltas or GitHub stars | Verified retired and Pro about 30% broken ([OpenAI](https://openai.com/index/why-we-no-longer-evaluate-swe-bench-verified/); [OpenAI](https://openai.com/index/separating-signal-from-noise-coding-evaluations/)) [V]; no community pack publishes a controlled comparison |
| Enforcing rules through Cursor's import of Claude hooks, or through Claude-only frontmatter that Cursor does not document | The import is off by default for Enterprises, maps only eight events (no `beforeShellExecution`), and documents no `failClosed` option ([Cursor](https://cursor.com/docs/reference/third-party-hooks.md)) [V]; Cursor documents no `tools` field for subagents ([Cursor](https://cursor.com/docs/subagents.md)) [V] |
